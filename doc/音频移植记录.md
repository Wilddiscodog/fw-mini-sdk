# 内置音频移植记录 (MIC 录音 + DAC 播放, V1.1.0)

> 日期: 2026-10-25 · 方法: 与 LCD 深挖同款 —— 先编译原厂参考工程
> (demo_DevKitBoard, CONFIG_AUDIO_ENABLE=1)作为基准, 逐项比对后实现,
> `MINI_AUDIO_SUPPORT` **默认 0**(本版固件不含音频, 代码已预置)。

## 1. 参考基准提取(原厂 demo_DevKitBoard)

| 项 | 原厂值 | 我们对应 |
|---|---|---|
| 演示模板 | `apps/common/example/Devkitboard_test/mic_test.c`(MIC→PCM cbuf→DAC 回环) | `app/audio_demo.c`(精简版回环自检) |
| 音频平台数据 | DevKitBoard.c: dac_data(hw_channel=0x05, ch_num=4, VCM 1000ms) + adc_data(MIC1 差分, isel=2, dump 480) | board.c 同数值; **差异: pa_auto_mute=0**(xiaolu 功放 MUTE 脚未定位, 原厂 PB02) |
| 设备注册 | `{"audio", &audio_dev_ops, &audio_data}` | 同(宏控) |
| 任务表 | audio_server(16,512,64) / audio_mix(28,512,0) / audio_decoder(30,1024,64) / audio_encoder(12,384,64) | 同 4 项(宏控注入 task_info_table) |
| 库 | audio_server.a(+大量编解码库) | **仅 audio_server.a**(PCM 回环不涉及格式解码; 试链接零缺符号实锤) |
| app_config 音频宏 | CONFIG_AUDIO_MIX_ENABLE 等 | 逐字拷贝进 MINI_AUDIO_SUPPORT 门控块 |

关键结论:
- `audio_dev_ops` 就在 audio_server.a 内(不在 cpu.a), 单库即可。
- `server/audio_server.h` 的 union audio_req **无宏门控**(布局固定), 不存在
  LCD 那类结构体错位风险; CONFIG_* 音频宏只影响应用层 demo 代码。
- server 框架(server_open/request/close)与底层 audio_dac/audio_adc 符号已在
  我们现有链接集(common_lib/cpu.a), 无需新增。

## 2. 实现(MINI_AUDIO_SUPPORT 门控, Makefile 默认 0)

| 文件 | 内容 |
|---|---|
| app/include/app_config.h | 音频宏段(MIX/PS/采样源/通道/增益, 逐字对齐参考工程) |
| app/board/wl82/board.c | dac_data/adc_data/audio_pf_d/audio_data + 设备表项 |
| app_main.c | task_info_table 注入 4 个音频库任务 + audio_demo_start() |
| app/audio_demo.c | MIC 16k 单声道 PCM → 8K 环形缓冲 → DAC 播放, 10s 回环 + 3s 停止循环 |
| Makefile | `AUDIO_LIB` 变量(LFLAGS `:=` 立即展开, 变量必须先于其定义——首次试链
  audio_dev_ops 未解析即此因) + `-DMINI_AUDIO_SUPPORT=$(var)` 注入 |

## 3. 验证

- `make.bat MINI_AUDIO_SUPPORT=1`: 编译链接通过, map 确认 audio_dev.c.o 从
  audio_server.a 拉入、demo 字符串入固件(无其它缺符号)。
- 默认构建(宏关): clean 全量后 app.bin 无任何音频符号(增量构建切宏必须 clean,
  与 LCD 轮次同教训)。
