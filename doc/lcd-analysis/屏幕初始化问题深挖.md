## 1. 闭源 emi_write 还原 (0x0202b9ce)

```c
int emi_write(dev, buf, len):
    if (sem_en[109] && busy[110]) emi_wait_send_ok();     // 上一次发送未完成: 等
    mode = 配置 & 0xF:
      1(2线?): len<3 或 len 为奇数   → puts("warning len no align 2bytes")
      2(4线?): len<5 或 len%4==0     → puts("warning len no align 4bytes")
    if (len < 5):                                        // 命令字节路径
        memmove(emi_buf@0x1c14dc8(内部RAM), buf, len);   // 短写一律先拷进内部对齐缓冲
        buf = emi_buf;                                    // → 单字节命令无对齐要求
    if ((u32)buf & 3) → puts("err in emi dma data address no align 4bytes"); return -22;
        // ★ ≥5 字节的 DMA 写: 缓冲必须 4 字节对齐, 否则报错且一个字节都不发
    busy[110] = 1;
    EMI_DMA_REG(0x41400)[0]=buf, [4]=len;                // 只交指针+长度, 无地址范围检查
    if (!sem_en[109]) emi_wait_send_ok();                // 非 sem 模式: 忙等
    return len;                                          // sem 模式: 异步立即返回
```

`emi_wait_send_ok`: sem 模式 = `os_sem_pend(sem, 200 tick)` **让出 CPU**(2s 超时报
"emi write timout"); 非 sem 模式 = 按 HSB 时钟换算的**有界忙等**(~1M 拍)。
`emi_ioctl(EMI_USE_SEND_SEM)`: 建 sem + `request_irq(27, 优先级3, emi_isr)`。

## 2. 问题 A/B/C 结论

| 问题 | 结论 |
|---|---|
| A 任务/线程 | 原厂无专用 LCD 线程要求: 普通应用任务直接 `user_lcd_init()`(camera demo 用 late_initcall, UI demo 走 ui 框架任务)。我们的 lcd_test_task(prio8/2048 栈)等价, 无问题 |
| B 内存约束 | EMI DMA **可读 SDRAM**(原厂 clear_screen 喂 malloc 307KB)→ 与 USB DMA 不同, 缓冲类型排除; 唯一硬约束 = **≥5B 写 4 字节对齐**, 短写自动进内部 emi_buf |
| C 初始化次序 | 原厂 ili9481_init **第一行就 BL_ON**(面板序列之前!) → 背光是"驱动被选中+EMI open 成功"的可见判据; 且原厂无复位序列(rst=-1), 我们 JD9853 的 PB7 复位序列保留(DCS 规范时序) |

## 3. 我们链路与原厂差异清单(全部已预置修复, 宏未开)

| # | 差异 | 后果 | 修复(已入码, MINI_LCD_SUPPORT=0 不编译) |
|---|---|---|---|
| 1 | ili9341+jd9853 同时在注册表, 框架取第一个 | ILI9341 序列跑在 JD9853 面板上, 白屏 | V0.9.6 已修: 只编 jd9853 |
| 2 | 彩条走 lcd->draw → ui_send_data_ready 空桩 | 一个像素都写不出 | V0.9.6 已修: draw_lvgl(真实 SetRange+RAMWR+DMA) |
| 3 | **背光在 init 末尾** | init 中途失败/挂起 → PA6 永不亮, 无法区分链路断点 | **本轮修**: BL_ON 前置第一行(lcd_jd9853.c) |
| 4 | **fb 静态数组未显式 4 对齐** | u16[] 可能 2 对齐 → emi_write ≥5B 直接 -22, 整屏丢帧 | **本轮修**: fb 加 aligned(4)(app_main/cdc 两处; malloc 路径本就 ≥8 对齐) |
| 5 | EMI tw=DIV4 vs 原厂 ili9481 DIV6 | 240×320 小屏信号余量应够, 风险低 | 保留, 点亮异常再调 |
| 6 | USB 共存干扰 | V0.9.6/7 实测彩条高频刷屏后 USB 不枚举; sem 模式写本身让出 CPU, 干扰机理未定位 | 保留 V0.9.7 的隔离手段: 彩条延迟 8s + 2s/色低频 |

## 4. 回开宏后的分步验证方案 (每步一判据)

1. `MINI_LCD_SUPPORT=1` 编译烧录, **只看背光**: 串口出现 `[lcd] LCD_JD9853 init_start`
   的同时 PA6 应立即拉高(BL_ON 前置)。→ 若无 init_start: 问题在 dev_open("emi")/驱动选择;
   若 init_start 但 PA6 低: 查 PA6 引脚复用(原理图 PA6_LED_PWM)。
2. `config succes` 后应自动全屏刷彩条(低频)。→ 黑屏但背光亮: EMI 数据通路问题,
   优先查 tw 时序与 D0-D7 接线(原理图 PC1~PC8)。
3. 彩条正常后观察 USB 枚举是否仍正常(8s 延迟已错开)。→ USB 挂: EMI/USB 干扰待专项
   (备选: 给 EMI 写加节流, 或 USB 枚举完成前不刷屏)。
4. 触摸 CST816(id 0xB6)最后联调。
