# fw-mini-sdk 外设移植计划与现状

> 对照原厂 AC79NN_SDK 梳理的外设移植清单与计划。
> 原则: **每个外设一个 `MINI_XXX_SUPPORT` 宏,默认 0(只移植不启用)**;
> 启用方式 `make MINI_XXX_SUPPORT=1`(改后 `clean.bat`)。
> 驱动层级(cpu.a)与头文件在 mini 树中**本来完整**——差距只在:
> 设备表注册 + 平台数据 + 应用胶水 + 少数框架库。

## 2. 本轮移植内容(P1,全部默认 0)

统一模式(与原厂 `demo_DevKitBoard/board/wl82/DevKitBoard.c` 对照得出):
`app_config.h/Makefile` 宏 → `board.c` 平台数据 + `REGISTER_DEVICES` 表项 →
`app/periph_demo.c` 演示任务 → `app_main` 调 `periph_demo_start()`。

| 宏 | 设备表项 | 平台数据(需按硬件核对处) | 演示行为 |
|---|---|---|---|
| MINI_PWM_SUPPORT | "pwm1" | PA01 / TIMER2-OPCH2 / 1kHz 50%(**TIMER2·output_ch2 与 LCD 冲突需核对**) | 1kHz 50% 方波输出 |
| MINI_RTC_SUPPORT | "rtc" | 内部时钟 / RTCVDD 外部供电 | 每秒打印系统时间 |
| MINI_SD_SUPPORT | "sd0" | A 口 1 线 / 20MHz / CMD 检卡(**引脚需按硬件改**) | dev_open+在线打印 |
| MINI_GPCNT_SUPPORT | "gpcnt" | PC07 / PLL 480M / ch4 | 挂表待用 |
| MINI_HW_CRYPTO_SUPPORT | 无表项(直调 API) | — | AES-128 加解密回环 + SHA256 自检 |
| MINI_KEY_EXTRA_SUPPORT | 无(按键框架扩展) | TCFG_IRKEY/RDEC/CTMU 默认 0 | 拷源文件备用 |

## 3. P2 备料(库拷贝入树,不链接)

`fatfs.a` `audio_server.a` `media_app.a` `lib_mp3_dec.a` `enc_qr_code.a` `libqrcode.a`
→ `cpu/wl82/liba/`。启用时按 doc《BT_WIFI_外设移植记录》同款流程接线。

## 4. 启用流程(任意外设)

```
1. make.bat MINI_XXX_SUPPORT=1     (Makefile 顶部开关区, 改后 clean.bat)
2. 核对 board.c 对应平台数据的引脚/频率
3. app_main 的 periph_demo_start() 自动拉起对应演示任务
```

## 5. 风险与注意

- PWM 的 TIMER2/output_channel2 与 EMI LCD 可能冲突(LCD 线使用 output_channel),
  同时启用前需核对 `output_channel` 分配;
- SD 卡引脚为 DevKitBoard 默认,**必须**按实际硬件修改 `sd0_data.port`;
- RTC RTCVDD 供电方式(外部电池 vs VDDIO)按硬件选择,错误配置影响掉电走时;
- WDT/低功耗不建议在联调期开启。
