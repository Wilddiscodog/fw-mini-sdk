EMI 写屏语义【实测】

static const struct emi_platform_data emi_data = {
    .bits_mode = EMI_8BITS_MODE, .baudrate = EMI_BAUD_DIV8,
    .colection = EMI_FALLING_COLT, .tw = EMI_BAUD_DIV6,
    .th = EMI_TWIDTH_NO_HALF, .time_out = 1000,
};
dev_ioctl(hdl, EMI_USE_SEND_SEM, 0);  /* 异步推荐 */
  • ≥5B DMA 写须 4 字节对齐，否则 -22 且不发
  • <5B 短写进内部 emi_buf，无对齐要求
  • DMA 可读 SDRAM（对比 USB 仅 RAM0）
  • 面板 REGISTER_LCD_DEV：框架取第一个注册项

官方 UI 平台（ui_platform.c）

路径：apps/common/ui/ui_driver/interface/ui_platform.c（CONFIG_UI_ENABLE）。向 ui_core_init 注册 br23_platform_api：

ui_platform 中的 CPU/DSP 加速

文件开头定义了 pi32v2_fill_q15/q31、pi32v2_copy_q7/q31，用 pi32v2 硬件循环 REP 做成块填色/拷贝（DSP 风格内联汇编），在 br23_fill_rect 热路径调用。

#define USE_PI32V2_MATH  0      /* 默认关！改为 1 才走 DSP 路径 */
#define PI32V2_MATH_DSP
/* fill: pack 两个 RGB565 → 一次写 32bit；REP 循环 [%1++=4]=r8 */
/* copy: REP 循环 load/store 字拷贝行缓冲 */
#if USE_PI32V2_MATH
    pi32v2_fill_q31(color32, p32, count);
    pi32v2_copy_q31(_p32, __p32, width/2);  /* 后续行复制首行 */
#else
    while (count--) *p32++ = color32;       /* 纯 C */
    memcpy(...);
#endif
点说明
加速本质不是独立 GPU，而是 CPU0/1 的 pi32v2 SIMD/REP 指令加速 FB 内存填充与行复制
默认状态USE_PI32V2_MATH=0 → 量产默认走 C/memcpy；打开后对齐要求更严（指针 4 字节对齐、width 偶数）
适用操作大面积 fill_rect、同色行复制；draw_image/α 混合仍多为标量循环
与 EMI DMA 关系CPU 加速的是合成进 FB；刷屏另走 EMI DMA（可并行：双缓冲/信号量）
LVGL 侧官方 lv_port_disp.c 中 gpu_fill 被注释掉，未把 pi32v2_fill 接到 LVGL；LVGL 绘制仍为软件光栅
若要给 LVGL 加速填充，需自行实现 gpu_fill_cb 调 pi32v2_*，并保证色格式/对齐与 RGB565 FB 一致；刷屏仍建议双 buffer + EMI DMA。

LVGL 深度绑定（官方补丁）

原厂路径：apps/common/example/third_party/lvgl/LVGL补丁/；fw-mini-sdk：third/lvgl + third/lvgl_port（同款对接思路）。

层级文件/符号绑定点
任务lvgl_main_task / late_initcalllv_init → tick(1ms) → port_disp/indev → demo → lv_task_handler 循环
显示lv_port_disp.c双缓冲各 LCD_W×10 行；flush_cb → lcd_lvgl_full(xs,xe,ys,ye,buf)
屏驱lcd_drive / user_lcd_init与 sty UI 共用面板驱动与 EMI；只初始化屏时可单独调 user_lcd_init
TElcd_te_driver撕裂同步；摄像头合成等同框架；无 TE 时用 stub
输入lv_port_indev.c触摸 FT6236/GT911/CST816 等板级实现
FSlv_port_fs.c对接杰理 FS（可选）
配置lv_conf.h + 板级 LCD_W/H与 isd/屏驱动分辨率必须一致
/* 官方 lv_main.c 骨架 */
lv_init();
sys_timer_add(NULL, lv_tick_inc_1ms, 1);
lv_port_disp_init();   /* → user_lcd_init + 双缓冲 */
lv_port_indev_init();
lv_demo_widgets();     /* 或 benchmark/music */
while (1) { lv_task_handler(); }

/* flush → 硬件 */
lcd_lvgl_full(area->x1, area->x2, area->y1, area->y2, (u16 *)color_p);
lv_disp_flush_ready(disp_drv);
  • 深度绑定含义：LVGL 不另起一套总线驱动，flush 直接进原厂 lcd_lvgl_full→EMI；屏参/背光/复位与 sty 工程共用
  • 官方示例默认双 partial buffer（10 行×2），注释写明应用 DMA 与绘制并行——对应 EMI_USE_SEND_SEM 异步路径
  • 【实测 fw-mini-sdk】JD9853 + EMI8 + CST816；OTA 前须挂起 LVGL/EMI，否则与 Flash/WiFi 抢总线易 misalign
  • 任务优先级示例 11（低于 audio_decoder=30，高于部分网络）；重 UI 时可 #C1lvgl 与 BT#C0 错开

选型与约束

  • MCU 屏 → EMI；RGB 屏 → IMD(+IMR)；视频 OSD → IMC；贴图 → IMB
  • sty UI 适合表盘/资源包产品；LVGL 适合自定义控件与开源生态
  • 两者勿同时高频刷同一 EMI，除非分时/挂起一方
  • 写屏缓冲 aligned(4)；多面板驱动勿同编
