原厂 DEC/ENC/EQ/DRC/AEC/DNS 能力清单 + 双核分工

架构总览

采集 → 硬加速/audio_server → 播放/编码/协议栈

应用只面对 server_open("audio_server", …) + union audio_req（DEC/ENC/IOCTL）。硬件位域多未公开；音效/通话算法在闭源库 + 可选 HW EQ/ANC/SRC/SBC。

原厂能力②：EQ / DRC / 在线音效工具链

头文件：media/eq/audio_eq.h、media/drc/*、media/effects_adj.h、media/audio_eff_default_parm.h。

  • 硬件 EQ：IIR 类型 HP/LP/BP/HighShelf/LowShelf；段数 ≤ EQ_SECTION_MAX(20)；增益约 ±12dB；支持异步 EQ、淡入更新系数
  • 预设模式：NORMAL/ROCK/POP/CLASSIC/JAZZ/COUNTRY/CUSTOM
  • 系数来源：EQ_TYPE_FILE（eq_cfg_hw.bin）/ ONLINE（PC 在线调）/ MODE_TAB
  • 高低音：high_bass（默认约 125Hz / 12kHz，增益 ±12）
  • 动态 EQ：DynamicEQ_api + Detection
  • 多段 DRC：低/中/高/全带 + crossover；FR/RL/RR 分通路
  • MIC 混响链（effects_adj 命令字）：Plate Reverb、Echo、NoiseGate、啸叫抑制(Howling/Notch)、VoiceChanger、Mix Gain（KTV 类）
  • 音乐链扩展：VBass 虚拟低音、Surround、声道互换、LPF、DAC/ADC PGA 工具参数、通话上下行宽/窄带 EQ+DRC
  • 配置：TCFG_EQ_ENABLE / TCFG_EQ_FILE_ENABLE / TCFG_EQ_ONLINE_ENABLE；文件路径如 mnt/sdfile/res/cfg/eq_cfg_hw.bin
大量音效模块在 effects_adj.h 中以宏注释关闭（howling/reverb/vbass…），量产工程按产品打开对应 .a/.o。

做音频时双核如何分工

WL82 无「音频固定跑 CPU1」的硬绑定；分工靠 任务名绑核前缀、irq_info_table 与 优先级。

机制写法音频含义
任务绑核"#C0name" / "#C1name"OS 按名前缀把任务钉在 CPU0/1；原厂 demo 里 BT 常用 #C0btctrler/#C0btstack，音频任务名一般不带 #Cx（可迁移）
中断绑核irq_info_table {irq, prio, cpu}AUDIO/EQ/SRC/ALNK 等 demo 未强制；SOFT5→CPU0、SOFT4→CPU1 常见
优先级隔离decoder=30, mix=28播歌时抢占 app_core(15)/WiFi tasklet(10)，降低断音
  • 播歌/本地解码：audio_decoder + audio_mix 吃满一个核的算力窗口；另一核继续跑 app_core / 网络 / UI。EQ 尽量走 HW EQ，减 CPU 负担
  • 蓝牙通话：BT 控制器/协议栈常钉 CPU0（#C0）；MIC→aec_encoder→dns_encoder→编码 与 DAC 回放在高优先级音频任务上，与 BT 同核时需靠优先级错开，或把重算法任务显式 #C1
  • AEC/DNS：软件算法（可借 FFT 硬核），CPU 密集；宽频 16k + AEC|NLP|ANS|DNS 同时开时建议避免同核再跑 WiFi 重负载
  • KTV/多段音效：MIC 链（混响/啸叫）+ 音乐链（EQ/DRC/VBass）数据流通路长，优先 HW EQ + 降低段数/关 ONLINE 调试
  • UAC：uac_play/record 与 usb_server；双核时可用 #C0usb_msd0 模式减轻冲突

日常状态下双核分工（非音频专用）

角色CPU0（习惯主核）CPU1（习惯从核）
系统app_core、sys_event、sys_timer、多数驱动回调可跑协处理任务；软中断 SOFT4 常挂此核
连接BT：#C0btctrler / #C0btstack / #C0btencry（原厂双核 demo）未钉核的 WiFi tasklet/MLME/CMD 可被调度过来
网络部分工程把 WiFi 留在默认核；与 BT 同核时靠优先级适合扛 RtmpMlmeTask / 重收发（需实测调 prio）
音视频audio_server 控制面；USB/UI 事件高负载 decoder/enc/jpg 可自然漂过来，或显式 #C1
中断EXCEPTION 等关键；irq 未列表则多落创建核策略irq_info 第三列 =1 强制到 CPU1
「日常」并非芯片固化分工，而是 SDK demo 约定：CPU0=交互+协议栈控制面，CPU1=可扩展算力。音频是否占满某一核取决于是否开 MIX/EQ/AEC/DNS 与采样率。改绑核后必须保证 task_info_table 名字与库内 task_create("…") 一致（含 #C0/#C1 前缀）。

最小闭环示例

/* 播放 */
req.dec.cmd = AUDIO_DEC_OPEN;
req.dec.dec_type = "pcm";
req.dec.sample_source = "dac";
req.dec.volume = 80;
server_request(dec, AUDIO_REQ_DEC, &req);
req.dec.cmd = AUDIO_DEC_START;
server_request(dec, AUDIO_REQ_DEC, &req);

/* 录音 + AEC */
req.enc.cmd = AUDIO_ENC_OPEN;
req.enc.sample_source = "mic";
req.enc.format = "pcm";
req.enc.sample_rate = 16000;
req.enc.aec_enable = 1;
req.enc.aec_attr = &aec_param;
req.enc.channel_bit_map |= BIT(CONFIG_AEC_ADC_CHANNEL);
server_request(enc, AUDIO_REQ_ENC, &req);

约束与库依赖

  • 设备表需注册 {"audio", &audio_dev_ops}（ops 在 audio_server.a）
  • 板级 dac/adc/iis/plnk 平台数据见 asm/audio.h → audio_pf_data
  • 模拟直通：ladc_mic_to_daclr() / ladc_linein_to_daclr()
  • ANC 硬件块在 WL82.h，上层 API/产品化路径因方案而异，故事机等工程不一定启用
