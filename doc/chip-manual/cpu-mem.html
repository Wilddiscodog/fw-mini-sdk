CPU 与存储系统

双核 pi32v2、SDRAM/PSRAM/RAM0/Cache RAM、异常与调试单元

双核 pi32v2

两颗 pi32v2 32bit DSP 核(CPU0 主核跑系统与任务, CPU1 可跑算法协处理)。每核有独立 ETM(异常跟踪 PC0~PC3)与 EMU(栈溢出/除零/未定义指令等仿真异常), 全局 corex2 调试单元提供总线异常(WR_LIMIT/PC_LIMIT/AXI/SFR MMU)检测——SDK cpu/wl82/debug.c 的 exception_analyze 即逐位解析这些状态。

/* debug.c 异常路径(cpu/wl82/debug.c): 每核栈溢出检测 */
q32DSP(0)->EMU_SSP_L = (int)cpu0_sstack_begin;   /* 栈下限 */
q32DSP(0)->EMU_SSP_H = (int)cpu0_sstack_end;     /* 栈上限 */
q32DSP(0)->EMU_CON |= BIT(3);                   /* 使能栈溢出异常 */
/* corex2: PRP_WR_LIMIT_EN / C0_PC_LIMIT 等写保护与 PC 越界检测 */

存储器映射

区域起始地址说明
Flash XIP (SFC)0x2000120SPI NOR 直接取指, 长度=Flash 容量(≤16MB)
SDRAM0x4000120代码/大缓冲主战场, 2MB/8MB(isd_config SDRAM_SIZE)
RAM0(内部 SRAM)0x1C00000+TLB零等待内部 RAM, USB DMA 只能到本段【实测】
boot_infoRAM0 尾部双备份启动信息区(sdk_ld_sdram.c)
Cache RAM0x1F20000+I-CACHE 方式回收部分 cache 作 RAM
【实测】HUSB 的 EP≥1 数据面为 RAM DMA 缓冲(0x16800 桥), 仅能落在 RAM0(0x1C00000~) 段, SDRAM 缓冲会静默丢数据; EMI(LCD) DMA 则可读 SDRAM——两者约束不同, 详见 USB/显示章节。

SDRAM 控制器(SDR)支持 SDR/DDR/DDRII(isd_config: SDRAM_MODE=0/1/2), 默认 240MHz 源自 PLL3(SDRAM_PLL3_EN=1 时 USB2.0 可用); PSRAM 控制器(0x41500 区域)可外挂 PSRAM。

Cache 与 MMU

  • I-Cache / D-Cache 各 8 way(corex2 系统单元 CACHE_CON/DCACHE_WAY/ICACHE_WAY, csfr.h), 行长 32B(CACHE_LINE_COUNT); sdk_ld 以 FREE_DACHE_WAY/FREE_IACHE_WAY(≤7) 回收 way 作 cache_ram(0x1F20000+)
  • D-Cache way 在 CPU 与 PRP(外设总线主)间分配: dcache_way_use_select(cpu_way, prp_way); 另支持写直通区域 dcache_cwt_set 与 flush_dcache/flushinv_dcache(cache.h)
  • 非缓存别名窗口(免 MMU): NO_CACHE_ADDR() 把 ≥0x4000000 地址 +0x4000000 得 0x8000000 段非缓存视图; DMA 与 CPU 双视图一致用 __asm_csync/ssync 屏障【实测: USB/EMI 路径】
  • MMU 可选(CONFIG_MMU_ENABLE): 使能时 RAM0 起址放 2 张 TLB 表(每核一张, SDRAM 配置 0x2000×2=16KB); debug.c 异常源含 prp/c0/c1 的 rd/wr MMU 错误——两核与 PRP 外设主都过 MMU, 越权访问触发异常(exception_analyze 解析)
  • movable region(LTO 插件): sdk_ld 的 .movable.slot/stub 机制用于代码搬移到 RAM 执行
  • PC 限界(pc_rang_limit)与写限界(dev_write_range_limit)调试接口(debug.c)
